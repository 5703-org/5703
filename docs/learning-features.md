# Learning features

The assistant opens in textbook mode and gives a complete explanation with textbook citations. The source selector independently offers general knowledge. The teaching control chooses a complete answer or progressive hints. All controls, stored state and source visibility are tied to the signed-in account.

## Questions, hints and full explanations

Enter an ordinary question to receive a complete explanation. Select the hint control, or explicitly ask for a hint, to start a teaching task. The current problem retains its objects and conditions. Further hint requests advance help within that task. Concept comparisons begin with a comparison dimension; process questions begin with an initial condition or causal link; calculations begin with known quantities and a relevant relationship. The controller evaluates the actual problem and already delivered material.

Request a complete explanation to release the full solution immediately through the direct-answer flow. A new question or topic creates its own task. New topics default to complete answers. The independent textbook/general-knowledge choice continues to govern source provenance.

The answer, short answer, suggested follow-ups and ordinary source previews are checked together in controlled hint mode. If the finite check/repair budget ends without approval, the interface shows a terminal error and keeps the drafts private. A provider fault, a clarification request and insufficient textbook evidence have separate states.

## Inspecting an exact citation

Select an answer citation to see its claim-specific source: book, chapter, page and the approved passage. Highlighted text uses exact backend fragment identities and escaped text segments. More than one passage can support one claim. Full source access is an explicit action that records additional requested help and rechecks current source availability. Reloading restores the controlled ordinary preview.

Source positions refer to immutable cleaned SourceUnit characters, with processing/document versions and SHA256 checks. Mapping quality and clipped atomic blocks remain recorded. These positions identify extracted textbook text; diagram interpretation and PDF glyph-level highlighting have separate scope. Older answers retain their original source versions and compatible historical presentation.

## Learning memory

Open the memory page to enable memory for your account. It starts disabled. Once enabled, explicit long-term preferences, goals, course context and stated difficulties can be saved with their source. A stated difficulty is labelled self-reported. Assessment observations retain the question, learner response, scoring basis and evaluator version. A current-turn instruction applies to that request.

The page shows saved content, scope, version, source message and expiry. Edit a memory to correct it. If another edit has already changed its revision, refresh the entry and review your draft. Delete removes its content and derived snapshots; a content-free suppression record prevents an old background task from recreating it. The Undo-save action deletes the saved entry. Chat history has its own deletion operation.

Global memory off stops reading and extracting memory. Turning personalisation off for one question excludes both saved profile settings and long-term memory for that request. Current explicit instructions take precedence. An explicit subject preference overrides the global presentation setting within that subject: Biology can use detailed explanations while other questions retain the global concise setting. Relevant observations then help shape the explanation within these choices. Expired entries are inactive.

The memory summary reflects active items. Preview a question to inspect its Current Learner State and contributing entry versions. Source/scope, edit/delete controls and processing status make updates visible. Recognized explicit corrections affect the current request; ordered write events prevent delayed older work from restoring the previous value.

## Administration and research

Administrators save provider revisions in Models, select an explicit capability profile and test basic generation, structured output and the project contract. Answer and checker roles have separate recorded results; a checker can use its own saved configuration. Activation requires passing project-contract tests for the selected roles. The active request freezes its model/checker configuration and policy; changing an active model applies to subsequent requests. Diagnostics retain stage-specific errors and measured usage.

The teaching studies use five declared conditions (T0–T4) with matched initial evidence and distinct exposure controls. Supplied-information, strict reliability, packing/repair and memory policies have separate comparisons. Study labels, reference answers and scores remain in the evaluator workflow. Independent human evaluation uses blinded forms and actual submitted scores. The [current protocol](execution/week08-memory-v2-protocol-20260921.md), [execution record](execution/week08-memory-v2-20260921.md) and [runbook](runbook.md) provide the schedules and operations.
