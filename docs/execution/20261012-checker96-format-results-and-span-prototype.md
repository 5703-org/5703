## Smaller implemented interface

`span_interface96.py` replaces model-authored owner/anchor IDs, seven normalized field containers, calculation objects and support verdicts with original propositions, role spans, finite labels and integer action attachments. The program creates IDs, binds exact original coordinates, constructs fixed inspection containers and preserves selected/offered boundaries. Labels include EXPLANATION, METHOD, SCOPE, CONDITION, DIRECTION, POLARITY and MODALITY. Wrong but legal labels remain unreviewed; lexical coverage cannot prove complete compound-action semantics.

`quote_span_interface96.py` narrows the model boundary further. Its span is `[text_index,exact_quote]`. The program locates the quote uniquely and computes all character offsets; the model does no coordinate counting. It preserves labels and attachments without semantic repair. It records the original quote-only input digest separately from the program-expanded explicit-span input digest. Legacy normalized outputs and the older explicit-offset wire are rejected, not transposed into successful new responses.

Two provenance defects were found and corrected during independent offline review: overlapping duplicate quotations/focuses now use `find(start+1)` checks, and selected-proof eligibility includes the complete transitive explanatory dependency closure, including participants, qualifiers and referent spans. All before-fix source/receipts remain preserved. Even a correctly selected graph has no support verdict or scientific certification; these containers are incompatible with the old normalized semantic guard and require a separately tested consumer.

The core passed **32** affected synthetic controls, with seven independently rerun provenance/semantic-boundary probes. The quote-only boundary passed **8** affected controls, preserving legal wrong labels as unreviewed and rejecting six legacy captures. Targeted Ruff passed. The six old responses contain **38/38** exact uniquely recoverable quotes; this demonstrates span feasibility in exposed saved samples, not new-model accuracy or held-out HumanGold. No span/quote model request was made.

Under identical transport settings, the quote-only compiled wire sizes are **6,277/6,186 bytes**, versus the actually tested normalized-field **10,221/10,036 bytes**. This is serialized-byte accounting, not token or latency reduction. The wire changes are explicit new task/schema boundaries; no current failed output or selected-source conclusion is rewritten.

Two new repository modules are prepared: `generation/experimental_span_extraction_v1.py` is the exact reviewed core, and `generation/experimental_quote_span_extraction_v1.py` is the reviewed quote adapter with only its package import changed. Neither is registered or enabled by default.

## Is another serial call worthwhile?

| S02 | 4.6465711 s | 2.9560024 s | 2.3612982 s |

These three versions have different instructions, output caps and emitted source-frame amounts; the six observations are not a controlled latency distribution or a speedup estimate. They show an additional serial round trip of roughly **2.36-4.65 seconds**, without a structural-plus-semantic passing pair. On current evidence, inserting that extra round trip into the normal answer path is **not justified**. The smaller interface may reduce model responsibilities and wire bytes, but has no measured model-quality or latency benefit. Reusing an existing generation/checker call instead of adding a serial call is an unimplemented integration option, not a claimed saving.

No native Send-to-complete-answer, TTFT, p95, quality non-inferiority or 5-10-second acceptance was measured. Local binding-control elapsed time is not successful semantic guard cost.
