# Local administrator draft review

The 1 October candidate adds an on-demand private draft view to Response diagnostics. An administrator can inspect saved generated text and separately displayed source excerpts within the administrator's workspace. The view has no publication, checker override, external transmission or human-rating action.

`GET /api/v1/admin/failures/{request_id}/drafts` returns the strict `DraftReviewPage` contract. It reads only terminal interactive-chat requests whose sessions remain available. The response contains at most 50 generated revisions, with 12,000-character text limits and explicit truncation. Online-check raw records, provider output, prompts, memory contents and practice grading fields are omitted. Credential-shaped strings are redacted from visible text. Inspection remains a local read.

Source display requires an unambiguous saved evidence-ID/chunk-ID binding, membership in the request's frozen corpus release, a current active source in the same workspace and a matching SHA-256 of the chunk text. Each displayed segment must occur verbatim in that chunk. Disjoint segments remain separate excerpts. A missing historical binding is reported as `incomplete_binding`; a revoked, inactive, changed or unavailable source is withheld. Stored model-supplied titles and URLs are not trusted for attribution.

Three disposable-PostgreSQL integration tests passed in 3.58 seconds. They cover learner rejection, other-workspace and deleted-session rejection, refusal to inspect running work, response allowlisting, credential redaction, source revocation, changed source bytes and absent binding records. Ten frontend tests covering the new view and existing response diagnostics passed in 1.74 seconds. The view fetches only after the administrator presses Load private drafts, renders text without interpreting stored HTML and retains actual authorization errors. These tests use authored fixtures, make zero provider calls and establish the tested access and provenance boundary. They do not independently label scientific correctness or checker error rates.

## Feedback review scope correction

The same inspection found that the earlier administrator feedback list and review write selected feedback without a workspace filter. Both routes now select through the same available interactive-request scope as diagnostics. Another workspace's feedback and feedback belonging to a deleted session are excluded; a targeted review returns 404 and preserves the row. Same-workspace administrators can continue reviewing available learner feedback.

The [combined administrator suite](../../evidence/week09-continuation/20261001/admin-scope-focused-final2.log) passed five integration tests in 4.43 seconds. Two added cases cover the cross-workspace/deleted-session read and write boundary, ordinary-user denial and successful same-workspace review. The original three-test receipt remains retained. This closes the tested feedback scope defect; unrelated administrator endpoints retain their separate security checks.
