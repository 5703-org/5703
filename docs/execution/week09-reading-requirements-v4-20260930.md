# Week 9 reading-question requirement repair

An isolated run of the immutable V12 project over the published *Concepts of Biology* release found a supported-question delivery defect. The reader sent the exact page-131 selection from Chapter 5, section 5.1 with the question, “What is photosynthesis in this selected passage?” Retrieval returned eight real E5/pgvector candidates. The request nevertheless produced a saved `INSUFFICIENT_EVIDENCE` refusal with zero citations. The [baseline runtime receipt](../../evidence/week09-continuation/20260930/v12-selected-passage-chat-failure-summary.json) records the terminal outcome; the initial attempt's old, unpublished unit ID had independently failed with HTTP 410 and was not used for this diagnosis.

The requirement extractor read the section title appended for retrieval as a second science question and treated `selected`, `passage`, `textbook`, `chapter` and a chapter number as required subject terms. This made a relevant source appear incomplete. The new `question_requirements_v4` policy keeps the original question and verified reader selection in model context and preserves the section anchor for local retrieval, while deriving factual requirements from the user's question. It removes only a clear leading or trailing reading-reference adjunct. An explicit request to explain, summarize or clarify the selected passage remains verbatim for the model and checker, and is tagged as bound to the verified source instead of making `paragraph` a missing scientific term. This stops a redundant named-term lookup; it does not declare the source semantically sufficient. Negation, numbers, conditions and other non-reading question behavior retain the V3 extraction logic. Newly submitted commands freeze V4; historical commands without the marker retain V3 execution.

The deterministic mock extractor now uses that same resolved science question for its lexical excerpt match. This change only prevents the reader locator from becoming a false matching obligation. It does not make the mock generator semantically competent, nor does it change the real provider's answer prompt or existing corpus vectors.
