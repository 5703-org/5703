# Week 9 isolated source parser: implementation and validation

Newly queued source-processing jobs run the existing PDF/TXT parser in a separate Python process. The child receives one immutable source path, its expected SHA-256, media type, parser revision, and explicit input/output ceilings. It returns the parser's unchanged source-unit dictionaries through a temporary JSON result. This changes the execution boundary; it does not change the parser revision, source-unit transformation, `ProcessingRun.configuration`, configuration hash, chunking, embeddings, release rows, or saved answers.

## Execution contract

| Boundary | Current behavior |
| --- | --- |
| New jobs | `Job.payload.parser_execution=isolated_parse_v1` selects the child process. An explicit retry of a failed run also receives this marker. |
| Existing queued jobs | Jobs without the marker retain the inline parser route and their historical parser revision. Unknown markers fail explicitly. |
| Input | The parent checks storage-root containment and streams the original SHA-256 before spawning. The child repeats the hash check. The parent rechecks after parsing before applying supplements. `MAX_UPLOAD_BYTES` is the input ceiling, with a hard 512 MiB maximum. |
| Output | The child serializes UTF-8 in 16 KiB slices into a private temporary result, stopping before `PARSER_OUTPUT_MAX_BYTES` (default 256 MiB; hard maximum 512 MiB). The parent checks file size, reads at most the configured ceiling plus one byte, validates the versioned envelope, and removes the one output file and directory. A single randomized directory creation attempt fails immediately if storage is unwritable. |
| Wall time and cancellation | A call-level deadline starts before input preflight and temporary-directory creation. The parent polls the child, terminates it on job revocation or `PARSER_WALL_SECONDS` (default 900 seconds), and advances the worker execution fence during long parses. Deadline and cancellation checks run before accepting the result. |
| Credentials and diagnostics | The child receives an allowlisted environment and no database, model API, or signing-key variables. Its standard streams are closed; expected failures map to fixed error codes rather than exposing parser exception text. |
| Failure publication | Missing or changed source, input/output limit, parse error, invalid protocol, execution error, cancellation, and timeout do not publish source units or chunks. Failed runs can be explicitly retried. Existing quality quarantine still applies to successfully parsed units. |

The isolated process is **not an operating-system sandbox**. It shares the worker's filesystem permissions, and its peak resident memory and CPU usage are not currently capped by the operating system. The configured limits bound source bytes, serialized result bytes, and the polling period. Blocking operating-system calls to create a process, read a filesystem entry, or remove a temporary file cannot be forcibly interrupted from this worker thread; the deadline is checked when those calls return. A hard parent-process termination can leave a temporary parser directory for later housekeeping. Old queued jobs deliberately preserve inline parsing until they finish or are replaced. These limits should be included in full installed-runtime and hostile-file testing before claiming arbitrary untrusted-PDF containment.

## Focused evidence

The focused regression used local fixtures and a randomly named disposable PostgreSQL database on `127.0.0.1:15432`; the fixture dropped that database after testing. It did not update the published four-book corpus or call a paid answer model. The [final sanitized log](../../evidence/week09-continuation/20260930/parse-isolation-focused-final-20260930.log) records **38 passed, 0 failed, 2 dependency deprecation warnings** in 17.30 seconds; SHA-256: `1a215880386f2019c2417a85cba1f63b2284365d10ab181d5da827f83181649b`.

The regression checks exact parsed-unit equivalence and a different child PID, deletion of temporary results, a source changed after queueing, pre-spawn input refusal, partial-output refusal, child timeout and cancellation, credential exclusion, malformed PDF failure, unchanged configuration identity, legacy queued-job compatibility, failed-run non-publication and retry, and existing corpus/upload flows. It also checks a single directory-creation attempt on permission failure. Ruff lint and formatting passed on all eight affected Python files after the final adjustment.

## Official-PDF read-only boundary check

The 185,858,638-byte stored Concepts of Biology PDF has SHA-256 `da0ffc8585e172f04eb0abb08949087baf85cc229ef2736ef06e5aa17094b1f6`. An initial read-only call using `artifacts/storage` for scratch output appeared to run for more than 16 minutes and was manually interrupted. A subsequent five-second `faulthandler` trace repeatedly located the block in Python's `tempfile.mkdtemp`, before the parser child was started: this sandbox denies creating scratch directories in that production storage path while Windows `tempfile` retries the permission error. The initial duration therefore **does not measure official PDF parsing time**. The implementation now attempts one random directory creation and maps a refusal to `PARSER_EXECUTION_ERROR`; the [real storage-root check](../../evidence/week09-continuation/20260930/parser-acl-fail-fast-20260930.log) returned that code in 0.001 seconds.

A separate run used a deliberately writable empty scratch root, the same unchanged official PDF, and a 10-second wall limit. It returned `PARSER_TIMEOUT` after 10.003 seconds, removed its temporary result directory, and left the original SHA-256 unchanged. See the [timeout receipt](../../evidence/week09-continuation/20260930/parser-official-pdf-timeout-20260930.log). This validates the real-PDF child timeout path.

The [1 October full-book receipt](../../evidence/week09-continuation/20261001/parser-official-full-book-20261001.json) then ran the unchanged official PDF with the configured defaults: 512 MiB input, 256 MiB output and 900 seconds wall time. The real child completed in **10.527 seconds**, returning 753 units across all 613 physical pages, 749 ready and four blocked units, with 3,698,319 serialized bytes. The four blocked units and every quality warning remain recorded. The original SHA-256 was unchanged and no temporary result remained. This read-only diagnostic used zero database connections, database writes and provider calls; it did not republish or replace the existing source units or four-book release. The full parsed-unit record remains private. Successful full parsing does not approve the 725 visual-content warnings or establish operating-system resource containment. See the [completion and safety report](week09-source-safety-completion-20261001.md).
