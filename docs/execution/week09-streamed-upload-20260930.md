# Week 09 streamed upload implementation and validation

The administrator original-upload endpoint now processes an uploaded PDF or UTF-8 text file in 65,536-byte reads. It stages the bytes in a temporary file under `originals`, checks the configured size limit before writing the offending block, validates the media signature or incremental text decoding, and computes SHA-256 while reading. The default maximum remains 536,870,912 bytes (512 MiB), with a 413 response above the limit. The synchronous FastAPI handler runs in the framework's worker thread; the upload no longer allocates a single buffer as large as the configured maximum.

The stored original retains its hash-derived immutable filename, recorded byte count, media type, source metadata, and existing duplicate-hash behavior. Copying from the staged file to the immutable target is bounded to 65,536-byte blocks, and the target hash is checked before registration. The staged file is removed on success, validation failure, a propagated read cancellation, or a read error. A partially created target is removed if copying fails. A client disconnect is not itself proven to interrupt an already-running synchronous worker, and this change does not alter the existing database-failure orphan cleanup policy.

Focused unit coverage checks the read bound and oversize rejection, read failure and propagated cancellation cleanup, invalid UTF-8 cleanup, and partial target-copy cleanup. Integration coverage checks a UTF-8 sequence split across read blocks, an HTTP 413 after 65 bytes under a 64-byte test limit, retained hash and size, and the existing upload type, path, media, and duplicate behavior. The final combined run of the existing corpus-runtime module and both new test modules passed **23/23** with two dependency deprecation warnings. An earlier combined run passed **22/22** before the fifth new unit cleanup case was added; the subsequent standalone unit run passed **5/5**, and those five tests are included in the final 23. Ruff check, Ruff formatting check, and configured mypy also passed.

The first integration setup attempt could not connect to the default test database port. An isolated stage database was also unsuitable because its access rule did not permit the fixture to create its temporary test database. The successful runs used the local PostgreSQL test-server fixture, which created and removed a randomly named test database. These setup attempts did not establish endpoint failures. No paid answer-model call or corpus publication was part of this change.
