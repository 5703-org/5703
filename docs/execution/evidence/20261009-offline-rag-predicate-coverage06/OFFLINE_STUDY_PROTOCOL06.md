# Bounded biology evidence ordering and source-set coverage

This workspace-only experiment compares two orders of the same actual checker-wire pool: retained evidence order and the existing Main BM25 algorithm. The pool contains 13 evidence items, 67 immutable source fragments and the exact 86-character question. It is a candidate-local ordering experiment, not a rerun of corpus retrieval. The saved wire fields do not contain Dense scores, so no Dense or RRF arm is fabricated. It does not reconstruct the earlier 20 retrieved full chunks.

Each ranking item groups the original fragments of one actual evidence ID. Fragments retain their separate actual fragment ID, alias, evidence/chunk/source-unit identity, source offset, page, text/hash and completeness metadata. Newline joining supplies lexical ranking text only; it does not assert that disjoint source spans form one contiguous whole chunk. Every stage projects all unchanged fragments for its selected evidence items, without truncation, source changes or production budget changes. Character and original lexical-token counts describe this offline projection; they are not model token/window measurements.

Main `retrieval.embedding.tokens`, `retrieval.ranking.bm25` and `retrieval.lexical.LexicalIndex` definitions are extracted from their actual Python AST without importing embedding/runtime/encoder modules. BM25 parameters are k1=1.5 and b=0.75. The original physical chunk ID resolves ties. Actual index and reference BM25 orders and floating-point scores must agree. A socket/process audit denial is installed before source evaluation. No database, credential consumer, provider, model, native startup or protected seed/binder is used.

Both arms use k=1,3,5,10,13. Their candidate membership, source identities, query and source texts are identical. An independent AI analyst supplies ten repaired-claim requirements and four high-level question-facet requirements. Each complete support bundle is an AND of exact fragment aliases; bundles for one requirement are alternatives. Nested scientific-predicate and actual-citation-contributor groups are preserved in the annotation audit. A source fragment available somewhere in the frozen pool does not count unless its evidence item is actually selected. A compound predicate requiring F054 and F055 cannot pass when only one is selected. Every actual bound citation must contribute the declared complete source support. The study does not relabel these analyst relations as human Gold or imply model use/entailment.

Root's pinned `fragment_coverage_v1.py` measures complete bundle availability only. The new offline runner compares every stage's coverage and missing-fragment sets with an independent pure reference. Unknown IDs, duplicate IDs and empty bundles are rejected. Empty alternative lists mean no complete support was declared and remain uncovered; they are not silently promoted to a pass. Full-pool coverage equality is required across both orders.

Controls cover missing-one-of-AND, true alternative OR, every bound citation's contribution, unselected availability, invalid IDs, duplicate identities, zero-score tie ordering, top-k prefix consistency, Main index/reference exact equality, and omission under a synthetic whole-fragment character allowance. Synthetic budget controls do not truncate real source fragments or change production settings.

The output reports all ten stages and separates claimed-predicate coverage from requested-facet coverage. It is conditional on the analyst's source-support bundles for this exposed question. Source-set coverage is not retrieval relevance precision, full-corpus recall, answer accuracy, human agreement, learning benefit or a native publication gate. No complete answer is generated and no answer latency is measured. A local analysis runtime, if reported, is explicitly unrelated to Send-to-complete-answer time. No production default follows from this one-question comparison.

This offline experiment does not resubmit or bypass that action. Native protected fields are not inspected.
