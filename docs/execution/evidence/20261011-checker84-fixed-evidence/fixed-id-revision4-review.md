# Fixed original-text IDs, revision 4

The W candidate now uses `e`, `f`, `p:string` for requirement evidence. A complete nonempty fragment at most 1200 characters maps to its original ID, such as `F001`, and restores exactly the whole original text. A longer fragment has a finite catalogue of overlapping punctuation/paragraph-delimited sentence ranges, each at most 1200 characters. From each sentence start the compiler selects the maximal consecutive range within that cap. Each fixed `Q000001` ID maps to one immutable original fragment/range; the codebook contains ID and original locators without duplicating source text. The model chooses an ID, never calculates or emits offsets. A single over-cap sentence has no selectable ID, is explicitly recorded as unavailable and remains unchanged in the original packet. No source clipping, summary or synthesized proof is added.

This is a lossless projection on the represented domain. It is not an arbitrary substring roundtrip: `encode_full` rejects uncatalogued exact partial quotes without widening, even when a larger original block exists. Decode requires an explicit valid ID, matching fragment/evidence ownership and complete original block. Missing, duplicate, unknown, old numeric-coordinate, boolean and foreign references reject. All complementary references remain separate evidence objects. Given/derivation literal quotes remain unchanged. Original quote, evidence and reason caps remain unchanged.

Every original canonical field, status, basis, condition flag, unit judgment, reason, aggregate boolean, coverage value, identity, citation and repair reference is retained. Model-selected unit evidence must also occur in its own parent's actual citation assessment; no evidence is supplied locally. The immutable context hash now binds a wire/catalogue fingerprint as well as the entire original packet and unchanged canonical schema, rejecting stale coordinate contexts. A fixed ID establishes provenance only. Whole passages and sentence blocks may still omit conditions or be insufficient; negative judgments remain negative and all original canonical validators, source/unit gates and publication gates still run. Punctuation segmentation is not a semantic condition-boundary certificate.

The real checker-contract correction message can follow the complete packet. `prepare` now finds exactly one original user packet by top-level discriminator keys, using the existing `strict_json` parser. A user message containing an explicit quoted packet key followed by a colon must be an unwrapped strict object; lists, code fences, BOM wrappers, duplicate keys, nonfinite values and malformed JSON reject. User content beginning with `{` is strictly parsed even without a discriminator. Zero or multiple packet-like objects, including a complete packet plus a partial fake, reject. Natural-language feedback and valid non-packet JSON feedback retain their original text and order; only the original system message gains projection instructions. No packet wrapper is repaired or stripped. Selected input still passes the unchanged v1/v2/table decoding, scope guard and context construction.

The policy remains default `None`. Its ordinary enhanced E1 interactive textbook, typed-joint-V5/source-V2/reliability-V5 guard and provider guards remain unchanged. Both `json_schema` and `json_object` hydrate into the same full canonical output. The codec does not restrict `claim_patch_repair_v3`; each actual revision still needs its new frozen packet and the original complete terminal check. It changes neither the existing repair loop nor the call budget, and adds no model call or repair framework.

The saved 83 packet keeps all 71 fragments, 12 claims, 25 units, 14 citation assessments and two requirements. Exact canonical schema 7125 bytes becomes projection schema 6902 bytes. Same compiled wire 101143 becomes 105256 bytes (+4113); original user content and every non-message option remain equal. These are structural bytes, not model token/latency results.
