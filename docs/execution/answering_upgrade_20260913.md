## Design decisions

- Keep one modular backend, one durable worker, PostgreSQL/pgvector and one frontend. Add a bounded model-configuration module, not a gateway service.
- The administrator selects a provider preset or custom supported protocol, endpoint, model and credential. Advanced tokenizer/window/output/authentication options are grouped separately. Protocol compatibility is explicit; arbitrary incompatible vendor APIs are not advertised as supported.
- Save creates an immutable configuration revision. A connectivity test makes an actual bounded provider call and stores safe success/failure metadata. Activation requires a successful test of that exact revision. Editing never silently switches the active version.
- Encrypt credentials at rest using a deployment-local key, store only an opaque credential reference in immutable requests and experiments, and return only a key-present flag/mask to the browser. API/worker use the same private key material. Portable delivery excludes deployment secrets and private user history.
- Freeze the active answering configuration when a new chat request is submitted. Workers resolve its credential at execution. Running/queued work and previous answers retain their selected revision. Retain environment-driven operation when no administrator configuration is active. Evaluation uses explicitly frozen configurations.
- Retain the 3,000 evidence-token, 2,000 history-token, 512 summary-token, 1,024 chat-output-token and cumulative 4-call/180-second limits initially. Replace byte counts with model-compatible tokenization and identify any conservative estimate. Enforce the complete prompt plus reserved output against the configured model window.
- Separate candidate passages, submitted passages and cited passages in diagnostics. Learner source controls identify actual response citations. Citation identity validation is distinct from independent semantic support review.
- Rewording an existing answer may reuse its passages. Requests for examples, mechanisms, comparisons or additional knowledge may combine the prior topic with new retrieval. Preserve source visibility and snapshot identity.
- Admin failures list actual questions and safe stage/error/count information; it must not expose credentials, evaluator labels, raw provider reasoning or unrestricted command payloads.
- E0 remains no retrieval, E1 remains basic dense retrieval, and hybrid/reranking/chunking variants retain named conditions. No new chat optimization silently changes a frozen research condition.

## Implemented answering behavior and boundaries

The adapter now sends actual role messages through explicit OpenAI-compatible, Anthropic Messages and Gemini native transports. Azure authentication/API-version configuration and Ollama-compatible endpoints are supported through their declared protocol. Transport tests exercise payloads, headers, native response/usage parsing, strict JSON probes and refusal/error handling against local HTTP fixtures. Only DeepSeek `deepseek-flash` has the external live evidence in this checkpoint. The adapter does not follow credential-bearing redirects or silently switch providers. Managed configurations use `model-settings:<UUID>`; an intentionally absent managed key does not inherit an environment secret. Chat, benchmark and teaching execution resolve the exact frozen revision, not a later active pointer.

The DeepSeek run uses the locally pinned `deepseek-ai/DeepSeek-V4-Flash-0731` tokenizer at `7872f01b1d1fe23eabc4c98b48bffcef5a386062`, with verified tokenizer-file hashes. Model text tokenization is distinguished from provider-side framing and the undisclosed checkpoint behind the `deepseek-flash` alias. Complete serialized request counting includes instructions, role/history framing, summary, profile policy, evidence, JSON schema and output reservation, with an explicit protocol safety allowance. Unknown models may use a labelled character estimate only when configured to permit it; UTF-8 bytes are not reported as actual model tokens. Anthropic/Gemini native token-count calls, when selected, consume the same finite request-call budget. No cost is invented when a provider does not report it.

`CHAT_RETRIEVAL_CONFIG=configs/retrieval/chat_hybrid_minilm.json` enables a new, explicit interactive policy: real E5/pgvector dense and BM25 candidate fusion, at most 20 candidates, then the local learned `cross-encoder/ms-marco-MiniLM-L6-v2` at `233902d25c440f23af6f7d6e94d2946bac0bee0a`. Whole-source passages are selected under the existing token ceiling; a ranking score is never treated as proof that a passage supports a claim. The policy and hash are frozen at submission. Older queued requests without this policy keep their previous retrieval behavior. Missing configured model assets fail explicitly and never cause an implicit mock/lexical substitution. Benchmark E0 remains no retrieval and E1 remains basic dense R0 with its frozen depth; the interactive optimization does not alter either benchmark.

Restatements and source requests reuse only eligible citations from the resolved prior answer. Requests that extend knowledge retrieve afresh and can retain relevant prior evidence. Explicit subject names are recognized before subordinate style/example clauses, and a local pronoun is not replaced with an entire prior question. Prompt instructions ask the model to preserve relevant conditions, exceptions and alternative outcomes and to explain necessary terms for a beginner. These are instructions, not an automatic semantic-equivalence checker. The existing strict citation marker/set validator remains in place; the single format-repair allowance and at most two transient retries share the four-call/180-second budget.
