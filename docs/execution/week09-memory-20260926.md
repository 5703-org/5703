# Week 9 memory selection and application

## Research and scope

LongMemEval separates memory indexing, retrieval and reading and evaluates updates, temporal reasoning and abstention alongside information recall. This project uses that separation to measure selecting an applicable preference and following it in an answer as different outcomes. The project-specific fixture does not reproduce the LongMemEval benchmark. [Official ICLR 2025 paper](https://proceedings.iclr.cc/paper_files/paper/2025/hash/d813d324dbf0598bbdc9c8e79740ed01-Abstract-Conference.html), [author repository](https://github.com/xiaowu0162/LongMemEval).

E5 requires task prefixes and normalized vectors; its cosine scores commonly occupy a narrow high range. A cutoff needs local calibration. The frozen configuration uses `intfloat/e5-small-v2`, revision/tokenizer `ffb93f3bd4047442299a41ebb6fa998a38507c52`, 384 dimensions, `query:`/`passage:` retrieval prefixes, CPU, and the existing local model cache. A local-only availability check precedes model construction. No corpus vector changes or provider calls occur during scope matching. [Official model card](https://huggingface.co/intfloat/e5-small-v2).

## Implemented behavior

`personalisation/memory_v3.py` adds the opt-in `query_conditioned_memory_v3` selector. Disabled configuration preserves v2 selection and changes only the selector version and private diagnostics. Existing v1/v2 execution and the typed v2 writer remain available. The application freezes the exact semantic policy with each new request; `MEMORY_SEMANTIC_POLICY_FILE` is optional and unset by default.

Rules resolve known scopes first. At most 24 unresolved eligible scopes receive local E5 scores. Current explicit instructions, verified entry types and existing field precedence remain in force. A failed local model records a bounded error type and returns to rules. A semantic score establishes topic similarity only.

Conditional preferences trigger an owned source-message reread. The current memory version, active status, expiry, owner/workspace, source role, original quote and saved source hash are checked. Simple explicit topic conditions are recovered for the frozen view without modifying the stored record. Exceptions and ambiguous conditions are excluded with a clarification reason. The condition parser is intentionally finite; arbitrary logical conditions remain a future validation target.

Selection policy and per-entry diagnostics live in the revocable private snapshot. Generation receives the bounded typed state after these diagnostic keys are removed. Deletion and expiry continue to invalidate derivative snapshots. Normal public diagnostics expose counts and status, without original source statements.

The existing `/me/memory/preview` endpoint remains the v2 rule projection. Its choices match the default disabled-semantic path. Enabled experimental semantic choices are visible in actual request diagnostics; matching semantic preview behavior is a separate follow-up.

## Frozen applicability study

The fixture contains 64 assistant-authored cases: eight development scope groups and eight disjoint reserved groups, four related variants per group. Each group has scoped and conditional preferences with applicable and unrelated questions. This deliberately stresses unresolved scopes; it does not estimate average performance across all stored memories. All negative scope questions share one software-release question, which limits negative-topic diversity.

Cases, labels, source hashes and the grid were frozen before E5 execution. The fixed grid is 0.700–1.000 in 0.005 steps. Selection maximizes development true selections subject to zero development false selections, with the stricter cutoff breaking ties. Calibration was written before reserved evaluation. Thirty-two unique question/scope combinations used actual E5 vectors; the offline grid reused measured scores within the process.

| Development, v2 rules | 0 | 0 | 16 | 16 |
| Development, semantic supplement | 14 | 0 | 2 | 16 |
| Reserved, v2 rules | 0 | 0 | 16 | 16 |
| Reserved, semantic supplement | 14 | 2 | 2 | 14 |

Development selected 0.800. The two reserved false selections and two omissions remain recorded. The threshold is experimental and default activation remains disabled. Labels are authored applicability expectations; independent human ratings are zero. Reserved results have not been used to retune the threshold.

Raw cases, scores and labels are protected at `evidence/week09-generation/20260926/private/memory-selection/`. Public aggregate evidence is `evidence/week09-generation/20260926/memory-summary.json`. Exact calibration sources were retained in the protected work area with archive SHA256 `d95d024f35d74156d77321f32c092fac511a8c76c6a54478688bb5d333458803`. Later changes reject malformed policy JSON, report disabled-mode selected counts correctly and check local model availability; selection scores and cutoff decisions were unchanged.

## Real answer application pilot

Eight development cases produced 16 paired outcomes using real DeepSeek `deepseek-flash`. Both arms used identical question, profile, official textbook evidence, active provider configuration and four-call/180-second budgets. Real CPU E5, hybrid retrieval and MiniLM ranking ran against read-only isolated PostgreSQL before generation. All inputs and source maps were frozen before calls. Generation executed the protected 789-file Week 8 baseline (`evidence_reliability_v3`) from archive SHA256 `ea41a00b977624f74d6e5e15574ab8e01b649c4d163eb7a96312cde9d33037f3`; concurrent Week 9 generation edits were outside this comparison.

| Observation | Rules | Semantic supplement |
|---|---:|---:|
| Outcomes | 8 | 8 |
| Delivered answers | 6 | 6 |
| Provider calls | 19 | 21 |
| Reported total tokens | 208,912 | 235,352 |
| All-outcome median generation time | 8.125 s | 7.697 s |

Three failures were `SEMANTIC_CHECK_FAILED`; one was `CONTEXT_LIMIT`. All attempts, raw outputs and unsuccessful outcomes are retained. Provider token totals include generation and checking. Monetary charges are unavailable in provider receipts. This small sequential pilot does not establish a latency improvement or preference-compliance improvement. Automatic answer lengths vary without a consistent increase for the semantic arm. Preference compliance requires independent review.

The protected pilot is `evidence/week09-generation/20260926/private/memory-application-pilot/`. Blinded review materials are in sibling `memory-application-reviews/`: 16 shuffled cards, two independent 16-row blank forms, scoring guide and a separate coordinator mapping. Blank import validation reports zero human ratings and performs no imputation. The importer rejects duplicate reviewer/item pairs and numerical compliance scores for undelivered answers.

## Verification and reproduction

Focused checks passed: 43 v2/v3 unit checks, 17 disposable PostgreSQL memory lifecycle checks and two optional-memory preparation/revocation checks. Initial test-import, Windows temporary-directory and expanded-diagnostic expectation failures were corrected; these were software setup/contract issues, separate from the four real provider-pipeline failures above.

Use `python -m scripts.verify.week09_memory freeze --cases <protected-authored-fixture.json> --output <new-empty-study>` then `run` to create a new versioned selection study. The authored input file stays in protected storage. Use `week09_memory_answers prepare`, `freeze`, `run` and `summarize` for a development-only paired generation pilot; the freeze stage requires the protected baseline archive and private database connection file. Existing studies refuse overwriting calibration or interrupted paid calls. `week09_memory_reviews export` and `import` prepare and load actual reviewer forms. The exact paid-study runner is retained as `frozen-runner.py` in the protected pilot directory; later source annotations add no new calls or outcomes.
