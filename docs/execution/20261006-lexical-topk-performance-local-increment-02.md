# Exact lexical top-k performance increment, correction 02

The final change in `retrieval/lexical.py` selects top-k with `heapq.nsmallest` using the original `(-score, chunk_id)` key. If a permitted extreme BM25 parameter produces NaN scores, it retains the original full sort. The matching regression is added to `tests/unit/test_retrieval_cache.py`. These are descriptive **whole warmed lexical-search** timings on deterministic synthetic data. The roughly 0.51/0.71 ms p95 savings include NaN detection. They do not measure DB validation, queueing, dense retrieval, reranking, generation, checking, publication, HTTP observation or visible page rendering. They establish neither a 30% page-p95 reduction nor teaching-quality noninferiority. The fixture's 4096 rows are unrelated to a model completion-token cap of 4096.

The five unchanged queries include empty/absent terms; both layouts and all observations are retained. Percentiles interpolate linearly at `(n-1)*0.95`; no speed threshold was asserted. Input and source hashes were unchanged during execution. The second run is the final candidate's measurement, not a selection of the faster first run.

Seven pure unit tests passed in 0.33 s, including the existing 920 finite reference comparisons and a new 24-combination NaN-aware regression (six row permutations, k=1/2/3/4). The final fallback passes without changing accepted parameters or relabelling invalid scores.
