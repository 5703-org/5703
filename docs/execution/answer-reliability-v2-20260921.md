This keeps causal links and qualifications available separately from the narrower displayed highlights. `joint_check_v2` distinguishes textbook claims, exact learner givens, derived calculations, nonfactual text and evidence limitations. A textbook claim's own inline marker must match the supporting fragment's evidence identity; a citation elsewhere in the answer cannot cover it. Checker claims must cover the actual exact answer/short-answer claims. Source atomicity, fragment identity, visibility, task help policy and cumulative exposure checks remain enforced.

## Amendment 02: learner-given formula and conditional derivation

Before formal calls, the derivation contract was extended with required `formula_basis=textbook|problem_input`. There is no implicit default: the first development pilot exposed the risk of treating an omitted basis as textbook. A textbook rule requires an exact quote in a complete source fragment. A learner-given rule requires its exact quote in the current question/problem and `formula_fragment_id=null`. Supplied values require exact source/learner quotes and consistent numeric values. Explicit standalone cardinal words zero through twenty are normalized to their numerical values; articles, ordinals and compound phrases are not inferred. A restricted Decimal arithmetic interpreter checks the submitted expression and stated rounded result; arbitrary code, nonfinite values, changed givens, mixed source identities and clipped source formulas fail.

This local check proves arithmetic and quote consistency only. Formula applicability and unit validity remain explicit model judgments. A conditional result derived from a learner-provided rule has public `support.status=null`, `check_state=conditional_derivation_checked` and `derivation_validation.conditional_on_given_rule=true`. Its public metadata identifies `formula_basis=problem_input`, `scope=arithmetic_and_exact_quotes_only`, `formula_and_units=model_judgment_not_independent` and `human_rating=null`. It does not acquire an invented textbook citation. Actual background/method claims still need their own exact textbook citations. Expressions, input proofs, computed private values and checker rationale are excluded from the public projection. Historical support metadata remains nullable.

For Memory V2, the versioned prompt follows current instruction > applicable explicit scoped preference > saved global profile default > other applicable memory. Legacy memory wording is preserved. Memory remains untrusted learner context and cannot supply scientific support; copied prompt segments are redacted/fingerprinted in persisted trace metadata.

## Amendment 03: exact citation correction and lossless checker encoding

The first two six-case development pilots remain separate immutable attempts: pilot 01 published four answers; pilot 02 published three. These counts do not establish an improvement. Pilot 01's DNA direct answer contained an uncited factual opening, while the supplied ideal-gas problem exposed the omitted formula basis and the explicit word “One” normalization gap. Those two cases answered in pilot 02, which instead retained an ATP context-limit error and two substantive/source-binding check failures. No formal outcomes were used to choose these repairs.

The amended v2 repair path can correct citation markers deterministically only when every factual claim already has a positive support verdict, all teaching/coverage controls pass, and the only local issues are exact inline citation-to-source mismatches. Each original claim must still match the exact answer substring, and the checker-selected fragments must exist and be complete. `generation/binding_repair.py` edits markers only, verifies that the non-marker prose is unchanged apart from marker-adjacent whitespace, rebuilds citation identities and the delivered projection, and requires a fresh semantic check. It cannot publish from the first verdict. Ambiguity, partial support, unknown/clipped fragments, factual failures or any other structural issue use the ordinary model-repair path. A failed new check remains a failure.

This path normally consumes generation + check + recheck, or three calls, while C2's generic model repair consumes generation + check + model repair + recheck, or four. Both keep the same four-call/180-second ceiling. Per-attempt method/origin and actual call counts are recorded; a computational saving is not treated as a semantic score. The C2 contrast therefore includes this registered repair mechanism and its actual call count.

The third six-case development pilot retained four answers and two failures. Its final calculation proof used a correct rounded value with an exact Unicode scientific-notation quote; local numeric comparison previously supported ASCII exponent notation only. The bounded correction normalizes superscript exponent digits/signs for numeric comparison without changing the quote or tolerance. Both final retained derivations validate in a local replay; no new semantic judgment or publication is inferred. Incorrect values, changed exponents and false source/formula quotes still fail. The remaining hint failure omitted a required checker field at call four and remains `CHECKER_INCONSISTENT`; no default field or extra retry was added. [The retained diagnosis](../../evidence/week08-memory-v2/20260921/answering/development-pilot03-diagnosis.json) preserves result hashes and distinguishes arithmetic replay from actual provider outcomes.

Before a checker call, the entire request plus reserved output is counted. If repeated fragment-field names overflow the window, the identical fragment bank is encoded as a column table with explicit column names; all fragment identities, evidence identities, block kinds, completeness flags and exact source text remain present. The final serialized request is counted again and can still fail `CONTEXT_LIMIT`. No hidden source truncation or higher window is used. For retained pilot 02 P01, the current object encoding measured 12,774 input tokens plus 4,096 reserved output; the lossless table measured 10,086 plus 4,096 against the same 16,384 window. All 114 fragments and every other payload field round-trip identically. [The local measurement](../../evidence/week08-memory-v2/20260921/answering/development-pilot02-lossless-table.json) used the pinned tokenizer and retained input, not a new provider call or judgment.

## Offline judging and paired analysis interface

`evaluation/memory_v2/judging.py` is evaluator-only. It freezes all 552 registered rows, the exact originating study/run identities, generation-result hashes, private authored references, applicable rubric fields, model configuration, prompt/schema and current code hashes before any judge call. Missing outputs stay present with no payload. It rejects an altered schedule, another study's run, duplicate result roots or unscheduled result files. The judge sees actual submitted evidence and delivered current/prior surfaces, but no arm label, online verdict, private claim proof or selected memory state. Memory expectations are private authored evaluator labels, never new product input. Same-provider/model-family bias and absent independent human ratings are explicit.

From the project root, preparation and execution use these interfaces (placeholder paths must identify the frozen private study and its immutable configuration):

```powershell
python -m evaluation.memory_v2.judging prepare --source PRIVATE_SOURCE --runs ABCT_RUN MEMORY_RUN --configuration JUDGE_CONFIG_JSON --output NEW_PRIVATE_JUDGE_DIR
python -m evaluation.memory_v2.judging run --output NEW_PRIVATE_JUDGE_DIR --allow-live
python -m evaluation.memory_v2.analysis --judge NEW_PRIVATE_JUDGE_DIR --output NEW_ANALYSIS_JSON
```

Each offline judgment has its own two-call/90-second budget and at most one schema-only repair. Provider errors do not automatically retry. Started/finished attempts and raw private output are durable; uncertain reservations are not replayed. Elapsed time includes preprocessing/counting and is checked before calls and publication. Source drift invalidates a candidate judgment instead of publishing it. A persisted authentication/quota stop is replayed on resume and prevents later calls.

A separately measures factual correctness and supplied-information behavior; source support is inapplicable there, and direct complete answers are explicitly permitted. B/C measure science, coverage and citation support. T also judges useful help and all current/cumulative disclosure surfaces. M also judges applicable preferences, stale/scope misuse, current-instruction precedence and unsupported learner inferences. Binary/null applicability is strict. No answer or absent rating becomes a fabricated factual-error judgment. [The current A1 observation](../../evidence/week08-memory-v2/20260921/formal/judge-applicability-observation.json) retains 17 invalid judgments among 19 delivered answers; two inspected failures supplied a score where null was required. The remaining two judged answers do not establish general A1 accuracy. This is a judge-contract/coverage limitation, with no post hoc scoring or replay.

Analysis reports planned, eligible, attempted, delivered, answered, refused, clarified, failed, unexecuted and judged denominators. A2 without actual human confirmation remains planned but ineligible. Judged-answer dimensions are separate from conservative all-planned end-to-end success. Primary B2−B1, T2−T1 and M4−M3 comparisons keep each family/trajectory's repeated turns together, use equal-weight paired cluster means and 10,000 percentile bootstrap samples with seed 20260921. Missing/failed/unjudged rows count as unsuccessful only in that explicitly conservative composite. M3/M4 typed-field diagnostics use partial authored required/excluded labels; precision remains null. M0/M1/M2 typed recall is inapplicable because their original representations are not comparable. Matched final-answer judgments still apply to every M arm.

The analysis exposes measured token sums with unknown counts, never prices missing usage as zero, and leaves currency conversion/tariff reconciliation to a separately frozen cost report. Its attempt scope is answer/checker/repair and offline judge only; extraction, summarization, preparation and diagnostic receipts must be added separately.
