# Week 9 generation contract and provider boundaries

This implementation follows the frozen [Week 9 protocol](week09-generation-protocol-20260926.md). Generation domain owner: Sijin Lu. Integration owner: Xianshu Zhang. Implementation and automated execution: Codex. This record describes software contracts; model judgments and operational delivery counts do not establish independent answer quality.

## Version and exact evidence contract

New requests use `evidence_reliability_v4`. `generation/checked_v3.py` and `generation/reliability_v3.py` retain the preceding v3 implementation, with the former importing the preserved latter. Existing v2 and legacy dispatch remain executable. The complete pre-change 789-file archive is recorded in the protocol. New fields in `GenerationRequest` are optional frozen dictionaries `generation_policy`, `teaching_plan`, `evidence_coverage`, and the explicit string `provider_output_policy`.

The checker classifies every exact claim independently. Its strict variants carry only the fields applicable to textbook support, a learner-given quotation, a calculated derivation, procedural guidance, an evidence limitation, or explicitly selected general knowledge. Factuality is derived locally from the independently selected basis, removing contradictory pairs such as a textbook basis and a false factual flag. This schema cannot prove that the selected basis is semantically correct; independent review remains required.

For each exact draft claim, the checker receives its actual adjacent evidence IDs and the immutable fragments allowed for each ID. In controlled hints, the allowed fragments are restricted to the actual displayed blocks. Each cited source must be assessed once as contributing support, irrelevant, or contradictory. Complementary sources can jointly support a compound claim. The checker judges the actual citation set instead of requesting a preferred replacement bibliography. Wrong evidence-to-fragment bindings, missing citation assessments, irrelevant sources, contradictions and unavailable fragments block publication. Exact source hashes, complete atomic blocks, derivation calculations, display limits and cumulative disclosure retain their existing validation.

The original typed judgment and actual binding table are retained privately alongside the normalized internal judgment. General-knowledge factual status remains separate, with textbook support marked not applicable. A procedural hint may remain citation-free only after independent claim and teaching checks. Ordinary direct textbook answers continue to require a complete supported answer.

## Repair and final delivery

An answer repair receives the rejected draft, exact claim spans, individual issues and a bounded repair plan. Unaffected approved claim text is protected in its original response field and order when the global disclosure controls permit it. A repair changing protected text is rejected before publication. Repaired content, citations, source display, question metadata and cumulative disclosure undergo a fresh complete check. The same four-call and 180-active-second owner remains authoritative, including retries and native token-count calls.

A checker-contract repair changes only the judgment for the same immutable draft and display. Semantic answer repair changes the proposal and requires a separate final check. Raw model drafts and pre-check tutor-question materialization remain recorded. Every physical call contributes once to usage and timing; `checker_contract_repair` contributes once to `checking_ms`.

When a draft has no actual inline citation, its checker cannot invent one in the actual-binding record. V4 routes that missing attribution to answer/citation repair instead of treating the empty citation set as a malformed checker response. The full support and derivation-source validation still blocks publication until the final checked draft has the required binding. This distinction is covered by both rejection and successful bounded-repair regressions.

## Coverage and teaching factors

The original task supplies the coverage requirements when a learner replies to a pending tutor question. Coverage separately records candidate evidence, packed evidence, omitted requirements and packing exclusions. These are lexical planning estimates and never replace semantic checks. Backend supplementary retrieval is limited to one named locatable requirement pass.

`coverage_context_v1` transmits each named requirement once, with candidate/packed coverage, missing term groups, matched evidence IDs and packing-loss IDs. Repeated token-match debug lists remain in the complete audit receipt. This reduces metadata duplication while leaving source text, conditions, claims and disclosure content intact.

The four teaching factors share the same provider, schemas and common engineering. B and D inject the explicit teaching action plan into both generation and checking. C and D select the actual displayed complete source blocks before checking. The display factor does not reorder or replace generator input evidence. Direct answers have no enabled hint plan. Scope-specific memory version `query_conditioned_memory_v3` uses the same explicit current-turn/scoped/default precedence contract while earlier memory versions retain their branches.

## Provider schema and empty outputs

`provider_probe_v3` tests the actual `TeachingDraftV4` and `ReliableCheckV4` contracts separately from basic connectivity and a small JSON object. The previous probe remains in `generation/probes_v2.py`. The compact checker schema removes presentation titles and represents mutually exclusive constant-basis variants as `anyOf`; the local strict schema keeps all validation constraints. Native provider schema subsets still undergo complete local validation.

The default `strict_v1` policy treats an empty response as a terminal provider failure. The experimental `json_example_once_v1` policy permits one changed-prompt recovery in the entire request, reserves the required final checker call, recounts the complete prompt against the same window and keeps the provider response mode unchanged. It does not silently switch services or relax the schema. Whitespace content and failed attempts are retained in protected callbacks for v4; the adapter default preserves prior retention behavior. Experimental recovery remains opt-in until actual provider evidence is recorded.

DeepSeek documents the need for explicit JSON instructions, a valid example and sufficient output reservation, and notes occasional empty JSON-mode responses. Those statements motivate a bounded experiment, rather than a guarantee of repair success. [DeepSeek JSON Output](https://api-docs.deepseek.com/guides/json_mode/). Constraint compliance and downstream answer quality require separate measurement, as reflected in [JSONSchemaBench](https://arxiv.org/abs/2501.10868). Targeted edits preserve supported content following the attribution-and-revision motivation in [RARR](https://aclanthology.org/2023.acl-long.910/).

New HTTP requests freeze `checker_payload_policy=lossless_checker_tables_v1`. Requests whose frozen command lacks that field retain `legacy_fragment_table_v1`. The release policy measures three complete checker requests and selects the smallest: the original objects, the existing source-fragment table, or new tables sharing repeated citation-allowlist records. The new table representation must decode exactly to the original checker data before submission. No evidence is clipped after drafting, no context window is increased, and the existing call/time budgets remain authoritative.
