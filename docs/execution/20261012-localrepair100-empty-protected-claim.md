# Localrepair100: use the existing bounded patch for eligible sole-defective claims

The existing ordinary checker and claim-patch repair path now handle an eligible draft with no protected claims without requesting a complete answer rewrite. The change is installed in `generation/checked.py`; two regression functions, with five cases, are appended to the existing `tests/unit/test_source_relation_units_v2.py`. The installed affected source-relation and local-patch test files passed **43 tests in 0.97 seconds**. Repository-config Ruff checks passed for both modified files. The original files are saved as byte-exact preimages, and the previous test file remains an unchanged prefix.

Before this fix, `claim_patch_repair_v3` required a nonempty `protected` list to select the smaller already implemented `ClaimPatch` task. A sole ordinary claim judged partial therefore received `chat_response_teaching_v5` for a full rewrite, even when all non-body gates were healthy. After the fix, that strictly scoped case receives `claim_patch_repair_v1`; the existing compiler edits the exact original claim span, reparses the complete response and invokes a fresh `joint_recheck`. It introduces no extractor, graph, output adapter, new schema, provider or default configuration.

The new alternative is limited to ordinary no-attempt direct textbook E1 interactive requests using the existing typed V5 checker and V2 source-relation contract. It requires full requirement coverage with no missing facets, healthy existing non-body gates, factual textbook claims with at least one negative status, and no non-source structural issue. Only the four existing source-relation/condition semantic defect codes qualify. Hint, practice, attempt, tutor, selection, teaching-boundary, malformed-contract, metadata, requirement and mixed defects do not gain this new admission. The helper uses the original trusted attempt-applicability flag; it does not invent an applicability decision.

The eligibility predicate relies on the validated native feedback builder. It is not a replacement schema validator or a scientific judge. Upstream source/identity/requirement validation remains in force. The existing nonempty-protected path stays intact, including exact approved-text retention. The same compiler rejects unknown, duplicate or protected claim edits, stale spans and foreign source markers. Original question, evidence, request requirements, metadata and all unedited response fields remain unchanged. Recomposition returns a candidate; it cannot publish before the same full semantic, citation, teaching, coverage and projection gates pass.

The call budget is unchanged: generation, first check, one bounded semantic repair and full recheck under the shared finite request budget. A missing reserved recheck slot stops before repair. These free checks do not constitute admission of the separate native paid experiment; it remains closed after Phase99 failed. The quote extractor stays closed, and a patch-format pass cannot replace source support. An unsupported population, operation, quantity/requirement or condition remains blocking at the fresh final check.
