# API and operator contract

## 21 September extensions

Memory owner routes now include `POST /me/memories` for explicit typed saves, `POST /me/memory/assessments` for attributable scored observations, `GET /me/memory/summary` for active-item projection, `GET /me/memory/processing` for ordered update status and `POST /me/memory/preview` for a question-conditioned learner-state preview. Owned edit/delete/source/settings routes remain available. State preview identifies contributing entry versions and applied scopes; private write-event details and other owners' content are excluded.

`POST /admin/model-configurations/capability-profile` returns an explicit compatible public profile to review and save. Compatibility tests distinguish answer/checker roles and basic/structured/project tiers. Started calls retain an idempotent record; a later uncertain outcome is not silently replayed. Activation binds passing project-contract results and the expected active revision. Existing encrypted credentials remain accessible only through the backend's managed path.

`FailureAttempt.provider_diagnostic` contains typed stage, HTTP status, provider code/type/parameter, request ID, finish reason, network category and submission flag. It omits provider-echoed messages and raw bodies. `FailureProcessing.memory` contains ready/disabled/unavailable status, policy version and an optional error code. The frontend displays these selected fields from the generated schema.

Public claim support distinguishes textbook, learner input, derived calculation, nonfactual and evidence-limitation bases. Conditional arithmetic from an exact learner-given formula exposes a nullable support status and `derivation_validation` scope; private arithmetic proofs and checker rationale remain server-side. Existing citation visibility and teaching-exposure fences continue across detail/history/source endpoints. [Implementation scope](../execution/answer-reliability-v2-20260921.md) and [current execution](../execution/week08-memory-v2-20260921.md) link actual validation.

All application routes are under `/api/v1`. Success is `{data,meta:{trace_id}}`; error is `{error:{code,message,details},meta:{trace_id}}`, with matching X-Request-Id. Authentication uses a bearer token returned at login, stored in browser sessionStorage and cleared at logout. Disabled users or stale token versions cannot access data. Another user's resource returns404; a learner's admin action returns403. [Runtime OpenAPI](../../contracts/openapi.json) now replaces the initial design export and is generated by `python -m scripts.verify.contracts --write`; typed frontend responses are generated and drift-checked from it. `contracts/models.py`, `contracts/learning.py` and `contracts/http.py` define the current DTO/envelope authority. [SPEC.md](../../SPEC.md) is the actual-system entry point; table summaries below are subordinate to the executable schema.

The learner landing route is `/chat`. `{content,use_profile,answer_mode?,teaching_mode?,task_id?,task_action?}` is accepted from the composer, with textbook as the default; choices, gold, history, owner and model fields are forbidden. Profile levels are beginner/intermediate/advanced; styles concise/detailed/socratic; initial language en; up to 20 self-reported topics of 200 characters each. An explicit invalid value is 422, while absent legacy policy gets a recorded intermediate fallback.

The [13 September upgrade](../execution/answering_upgrade_20260913.md) adds administrator model management without changing the learner command. `ConfigurationSave` contains `name`, `preset`, a validated `config` object, optional write-only `api_key`, and `clear_api_key=false`. Omitted/null key preserves the prior encrypted reference when creating a successor; clear explicitly removes it; replacement and clear together are invalid. Preserving a credential across a provider or destination-origin change is rejected unless the administrator explicitly replaces or clears it. Base URLs cannot contain userinfo, query parameters or fragments; Azure API version is a separate field.

Supported protocol identifiers are mock, openai, openai_compatible, local, ollama, azure_openai, anthropic and gemini. The config includes model/base_url, window_tokens/max_tokens/timeout_seconds, temperature/seed, token_limit_parameter, structured_output_mode, reasoning_effort, optional thinking_enabled, api_version/auth_header, and tokenizer provider/name/revision/local-path/fallback settings. A preset is editable configuration guidance; its existence does not certify an arbitrary model or provider account. `thinking_enabled=null` preserves provider behavior, while supported compatible protocols can explicitly enable or disable it. Mock checking and real transport checking remain visibly different.

`ModelConfigurationOut` returns id/group_id/revision/name/preset, public config/hash, has_api_key and a fixed `********` mask (or null), created_at, latest_test and active. `ModelSettingsState` returns all saved versions, active_configuration_id, active_version, source (database/environment) and encryption_ready. `ConnectionTestOut` returns id/configuration_id, status, model_mode, diagnostic_code/message, latency_ms, whitelisted usage and created_at. Failed probes are successful API operations with status=failed; they never enable activation or trigger a mock fallback. Activation conflicts use409. Encryption/decryption unavailability uses503 MODEL_UNAVAILABLE. No response contains plaintext keys, ciphertext, raw provider output or authorization headers.

Failure summaries identify the request/session/owner, actual question/state/response type, safe error code/message, creation time, provider/model/configuration ID and separate candidate/submitted/cited counts. Detail adds HTTP trace identity, stage states, finite budget counters, sanitized attempt summaries, retrieval query, candidate/submitted/cited chunk IDs, answer text and refusal reason. Counts can be null when historical traces did not record them; no missing historical count is invented. This is operational inspection, not independent evidence that a model answer is semantically supported.

Formal evaluation selects a managed version explicitly through an immutable evaluation configuration's `values.model_configuration_id`; it does not inherit the chat active pointer. The exact model version and mode enter the frozen environment hash and request command, while its secret is resolved only in worker memory. Scalar model overrides cannot be combined with that explicit managed version. The existing gold-free benchmark and independent teaching contracts remain separate, and live execution still requires the evaluator's explicit allow-live operation.

An answered ChatResponseV1 contains exactly schema_version, response_type, answer_text, short_answer, citations, refusal_reason, follow_up_questions, confidence. Example: `{schema_version:"chat_response_v1",response_type:"answer",answer_text:"Light energy is stored in sugars. [ev_001]",short_answer:"Chemical energy in sugars",citations:["ev_001"],refusal_reason:null,follow_up_questions:[],confidence:null}` is an authored fixture only and requires matching context. A refusal uses response_type refusal, useful answer_text, null short_answer/confidence, empty citations/follow-ups and a permitted reason. A provider error instead returns a failed job with a code such as PROVIDER_TIMEOUT and recovery guidance; it never masquerades as refusal.

Request states queued/processing/answered/clarification/refused/error/cancelled map to job states queued/running/retry_wait/succeeded/failed/cancelled. Polling returns only validated published answers. 409 covers session busy, stale revision, idempotency conflict and disallowed retry; 410 unavailable evidence; 413 oversize; 415 unsupported content; 422 invalid input/output schema; 503 dependency/configuration and 504 timeout. Errors include safe trace metadata, never raw credentials or private provider reasoning.

Administrative CLI equivalents: `app.cli migrate`, `seed-demo --confirm-dev`, account create/disable/reset-password, ingest --manifest, corpus-build --config, corpus-activate --release, corpus-rollback --release, job inspect/retry/recover, config create, feedback review, source revoke, cleanup dry-run/apply. Backup/restore use distinct confirmed targets. The tested command mapping and actual results are maintained in the runbook; initial design entries are not claims of implementation.

## Week 8 administrator processing projection

The existing authenticated workspace-scoped `GET /api/v1/admin/failures` and `GET /api/v1/admin/failures/{request_id}` routes add optional safe processing DTOs; the processing projection is additive. The separately introduced explicit answer mode is described below. `FailureCounts.filtered` records final admitted distinct candidates when present; candidates represent the distinct screened pool for the selected whole-query or facet-fallback path, submitted means actual model input and cited means saved response references. Whole-query counts remain separately visible when fallback triggers; per-facet counts are not summed across duplicates. Missing historical observations stay null.

`FailureDetail.processing` exposes bounded structured understanding, model/corpus/device identity, source-reuse and exclusion observations, lexical coverage/packing/citation/teaching summaries, measured timings and terminal diagnostics through explicit named fields. Raw snapshots, arbitrary trace/command JSON, provider response bodies and credentials are excluded. The administrator UI uses the generated OpenAPI types and explains that scores/lexical coverage/review flags are not independent semantic judgments. Formal evaluator/public input and managed-secret boundaries remain unchanged. [Implementation and tests](../execution/week08-delivery-20260916.md).

## Explicit answer mode — Week 8

`POST /api/v1/sessions/{session_id}/messages` accepts `answer_mode: "textbook" | "general_knowledge"`, defaulting to textbook. This is independent of provider `model_mode: mock|live`. Invalid modes return 422. Saved `AnswerOut` and embedded history answers expose the frozen `answer_mode` and `source_provenance`: textbook_evidence, model_general_knowledge_unverified, or benchmark_protocol. Old answers derive the textbook default; benchmark commands cannot enable the interactive general mode.

Explicit general knowledge does not load textbook retrieval configuration or use source evidence; its schema rejects citations and citation markers. There is no automatic switch after refusal or provider error. The learner selector and saved answer label expose the choice and limits. Cancellation/retry/regeneration preserve the frozen mode, existing ownership and idempotency rules; failed regeneration leaves the prior answer active. A general-mode mock adapter explicitly refuses independent factual knowledge rather than fabricating a simulated answer. ## 20 September controlled learning APIs

The existing message endpoint accepts optional `teaching_mode=direct|hint`, `task_id` and `task_action=auto|new|continue|more_hint|full_explanation`. Ordinary auto sends omit task ID and explicit mode: the server continues the same problem or starts a fresh direct task. The frozen `learning_task_v2` policy permits implicit navigation only for a subject-free continuation or a recognized same-problem follow-up. A newly named question starts a fresh task even when it begins with “another” or asks for a complete explanation; bare “another hint” and “full explanation” preserve the current problem. An explicit hint does not depend on profile level/style. More hint/full explanation must reference an owned task. New default commands freeze posthoc spans and T2; old commands and benchmark protocols are unchanged.

| Route | Input / response and authorization |
| --- | --- |
| GET/PATCH /me/memory/settings | Owner; `{enabled,version}` with CAS; opt-in default off |

| PATCH /me/memories/{id} | Owner `{version,content,scope,expires_at}`; explicit correction and derivative invalidation |

Exposure input binds `presentation_id`, optional evidence/claim IDs, `surface=answer|citation|full_source` and optional `parent_exposure_id`. A rendered source event requires its actual preceding citation-open/full-source receipt. Keys are 1–128 ASCII characters; the browser hashes its composite identity. Repeated keys return the same receipt after current visibility validation; changed content conflicts. Rendered means displayed, not read or understood.

`AnswerOut` adds presentation, safe attribution, teaching mode/task/help level and memory notices. `CitationView` contains plain text segments with highlight flags/fragment IDs; the browser does not render raw HTML. Hint answers suppress full evidence, profile and conversation snapshots. All answer/history/evidence reads enforce that projection. An explicit full-source event returns the original submitted source snapshot and original URL, while ordinary preview remains unchanged. Full explanation is a new checked answer request; there is no hidden complete-solution GET. A source unavailable after revocation remains 410 even for an idempotent expansion replay.

Direct mock responses remain explicitly mock with unverified semantic support. Hint T2 with no real checker fails as `SEMANTIC_CHECK_UNAVAILABLE`; the product never silently switches to T0. Checker diagnostic prose and private failed drafts are excluded from public attribution/errors. Source offsets denote immutable cleaned SourceUnit Unicode characters, not raw PDF glyph coordinates.
