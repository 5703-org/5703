# Memory expiry and frontend HTML policy

This Phase209 compatibility decision preserves the API's absolute `expires_at` timestamp and the existing date-selection convention. The date-only memory editor uses **UTC calendar dates**. A changed date is saved at 23:59:59 UTC on that date, clearing it sends null, and leaving the date unchanged preserves the existing saved timestamp verbatim. The date shown when editing an old offset timestamp is the UTC calendar date of that instant. The list and saved-time detail display the absolute time explicitly in UTC. This is independent of the browser time zone and daylight-saving transitions. Existing stored records are not rewritten or reinterpreted. This UI decision supplies no new evidence of server-side expiry scheduling; server due checks remain a separate acceptance concern.

The normal application is a top-level page and is not intended to be embedded by another page. Both the local Vite HTML owner and the production nginx HTML owner send CSP, X-Frame-Options, nosniff, Referrer-Policy and Permissions-Policy headers. API middleware is not evidence that a separately served frontend document received those headers.

Scripts and API connections use the same origin. Fonts admit same-origin assets and data URLs because the production CSS build embeds a small font. The exact loopback WebSocket origin is additionally admitted for local Vite HMR; production does not add it. Textbook original PDF pages are fetched from the owned API and displayed as blob images, so `img-src` admits same-origin, data and blob images. Downloaded files use ordinary anchors/blob downloads. No embedded PDF/object renderer was found in the current frontend. Framing the application and object plugins are denied. This does not prevent top-level source/download navigation.

KaTeX's layout uses inline style attributes and Vite injects development style elements, so style policy retains `unsafe-inline`. Script policy permits neither inline scripts nor eval, and no wildcard origin is added. This explicit styling tradeoff does not fix the separately tracked KaTeX dependency advisory or the citation traversal issue. Feature policy disables camera, microphone, geolocation, payment and USB because the current application has no corresponding flow. No HSTS, HTTPS redirect or OS security setting is introduced for local HTTP operation.

nginx's asset and HTML locations each set Cache-Control. The shared security-header include is therefore placed inside each location rather than relying on server-level header inheritance. The production Dockerfile copies that include alongside the server configuration. Actual served headers and browser asset behavior must be verified on the serving path before claiming coverage; configuration text alone is insufficient.
