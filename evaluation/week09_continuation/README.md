## Frozen study contract

`protocol.py` requires a catalogue with seven possible families: `textbook_qa`, `joint_tutoring`, `learning_memory`, `practice_feedback`, `visual_structure`, `safety_robustness` and `performance_recovery`. Every case has a unique ID, concept group, split (`development`, `pilot`, `reserved`), learner-facing `task`, source anchors where applicable, reference-label provenance and private labels. All paraphrases, turns and overlapping book concepts remain in one split. A textbook anchor must identify one of the four pinned official PDFs, original SHA-256, released chunk, exact text SHA-256, official URL and physical pages. Pilot and reserved freezes verify this relationship again through **read-only PostgreSQL**; they fail when the declared release is not active.

The candidate freeze records code, migrations, corpus release and manifest, model roles, policy versions, budgets, tariff, a pre-pilot `quality_thresholds_sha256` and fresh software-gate hash. Pilot and reserved freezes require `integration_status=verified_and_frozen`. A reserved freeze also requires a terminal pilot-based decision with independent judge calibration against those predeclared thresholds. The resulting `manifest.json`, `private-labels.json` and SHA-256 receipt are immutable. The product executor receives only `task`, arm and schedule ID. The case contract rejects answer keys and hidden evaluator labels inside the runnable task.

The teaching study freezes matched A/B/C/D arms, with the 26 September release as a separate engineering reference. A and B differ in teaching plan; A and C differ in displayed evidence selection. Original E0/E1 definitions remain intact, but the current Week 9 HTTP adapter runs only the candidate QA arm on these OpenStax cases. No same-case 26 September or E0/E1 comparison was executed. The old release is not pooled into the A-D factorial interaction. Memory, visual, safety and performance observations in the V7 pilot are candidate-only diagnostics; paired previous-versus-candidate effects remain unmeasured. Practice probes validate candidate draft structure and leave publication and independently labelled solvability pending.

`executor.execute()` provides a backend-neutral scheduling boundary. It writes a durable reservation before each external call, gives the backend no private label, and writes exactly one terminal record. An interrupted reservation remains unresolved and is never automatically resubmitted. Actual API adapters for each new learning workflow must use their final versioned DTOs and preserve application job receipts. A terminal record names the scheduled item, one explicit state, observed total elapsed time, actual learner-visible output if delivered, provider attempt count or `null`, token counters or `null`, the exact displayed sources, and optional stage/repair traces. These records are private evaluation data; sanitize exports before packaging.

`http_backend.py` connects only the candidate textbook QA family to the actual authenticated session/message/job/answer API. It creates a separate learner session per case, uses an idempotency key, requires live model mode by default, and preserves the job receipt. A separate read-only lookup against the isolated port-16532 clone may attach saved provider attempt and token/cache counters; lookup failure keeps those counters unknown without changing the delivered answer. Saved answer evidence is identified as request-level evidence, not certified as the exact generation input. The scheduler filters **both family and arm**, so memory, practice, visual, safety and performance cases cannot be sent as QA. The 26 September external release and original E0/E1 conditions require their own frozen runners; this adapter rejects those arms.

`teaching_backend.py` executes matched four-arm first-hint tasks against one frozen real CPU retrieval snapshot per concept group. It reuses the project's generation/checking core, applies the exact A/B/C/D planning and display flags, and retains learner-visible projections, displayed fragments, checks, failures, stage usage and pre-call reservations. Its candidate freeze must include `teaching_retrieval_sha256`; a changed preparation fails before a provider call. This is a generation/checking factorial with frozen real retrieved input. It does not include HTTP queue or fresh retrieval in per-arm latency.

The v5 preparation used learner-facing first-hint wording as a retrieval query, and both declared official teaching anchors were screened out. Its eight A-D attempts became preserved zero-call execution failures. [Sanitized v5 receipt](../../evidence/week09-continuation/20260930/pilot-v5-invalid-preparation.json). The successor freeze checks the exact candidate preparation hash, read-only CPU/release identity, frozen case IDs, and the presence and text hash of every declared official anchor in the **accepted** evidence list before it writes the study. The corrected subject-query preparation accepted 15 and 11 chunks and passed all six pilot QA/teaching anchor checks. Each successor still needs its own passed source gate and immutable candidate.

The additional pilot dispatchers use their actual scope: typed authored memory entries go through the current versioned local selector without a database write or answer; the visual probe reads the isolated administrator region API without certifying page geometry; practice requests a source-pinned model proposal and runs administrator structural validation while leaving the draft unpublished; safety and performance use isolated live HTTP chat, and a separate learner probes access to another owner's saved answer. The chemistry memory question remains exactly as authored after the product fix. Memory selection, visual structure and practice draft observations use a distinct `diagnostic_observation` terminal state and do not count as delivered learner answers. The V4 practice rows were cross-study idempotency replays; V7 bound their proposal keys to the manifest and source hash and a read-only database audit confirmed two fresh submitted calls. Practice semantic solvability, published feedback, visual geometry, actual memory use in an answer, previous-release comparison and student learning gain remain unmeasured by those probes. All V7 pilot arms are candidate-only except the teaching A-D factorial. Candidate-only paths cannot be presented as previous-versus-candidate effects.

The summary keeps all planned requests in its denominator. It distinguishes answer/hint/qualified partial, evidence refusal, clarification, provider or local failure, timeout, cancellation, empty or invalid output and security/policy block. It reports all/success/failed latency separately. Recorded zero provider calls cost zero for that request; conflicting nonzero token counters fail validation. Other unknown counters and interrupted requests remain unknown. Estimated cost uses the frozen per-million input/output/cache tariff. Invoice reconciliation is separate. Semantic ratings are grouped by reference-label provenance and by judge provenance. Successful delivery is never a proxy for correctness.

`blinding.py` removes the experiment arm, model and online checker decision from review packets. The offline judge uses a separate call and strict structured output; it receives the learner-visible text, actual source display, prior exposure and submitted-evidence scope. It cannot infer submitted context merely from a retrieved anchor. Its `ai_generated` ratings stay separate from independent human forms. Unfilled forms remain unscored. Judge calibration duplicates matched material and probes source order and injected instruction data; the observed agreement and failures are reported before choosing an acceptance threshold.

Statistical comparisons use knowledge-concept clusters. Repeats are averaged within a concept/arm before paired cluster bootstrap. The named teaching contrasts are B−A, C−A, D−A and D−B−C+A. Incomplete arm pairs are listed, never imputed. Secondary test p-values use Holm adjustment when supplied. Pilot estimates choose a conservative variance floor and record a precision target; they do not claim statistical power for real student learning gains. The simulated-student study requires a separate calibration of persona consistency, hidden-answer ignorance and response to guidance before any tutoring gain is interpreted.

`simulator.py` specifies five learner profiles and builds model input from an allowlisted visible transcript. Hidden solutions, answer keys and private evaluator labels cannot enter its input. Its calibration reports missing persona/ignorance/guidance labels explicitly. The v4 live one-turn probe submitted five learner calls; each ended `OUTPUT_TRUNCATED` at its 250-token budget, leaving all persona quality fields unscored. V7 raised the bound to 2,048 tokens and completed one-turn calibration; this remains an automatic simulator check, not a real learner-gain result. `attacks.py` reserves each adaptive attempt before calling an isolated frozen target, caps attempts and attacker tokens, and records both observed attack success and legitimate task completion. A lost target response leaves a reservation for reconciliation. An adaptive attack run remains pending.

`simulator_pilot.py` can run at most five learner calls and five separate automatic calibration calls from one actually published D-arm hint, only after the frozen pilot has delivered that hint. Learner calls receive the exact visible learner/tutor transcript and displayed sources. Reference passages and required points enter the calibration call only. The result retains each provider failure, invalid rating, usage counter and AI-only label. Even a calibrated one-turn student response does not establish a multi-turn trajectory or real learning gain.
